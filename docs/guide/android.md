# Building PakePlus for Android

PakePlus ships with a first class Android port. The Android application is a
Tauri v2 mobile application, the very same Rust code base that powers the
desktop builds, plus a small set of mobile specific helpers.

## Repository layout

| Path                                   | Purpose                                                                                             |
| -------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `src-tauri/src/command/cmds.rs`        | The bridge commands. Every command has a desktop and a mobile implementation.                          |
| `src-tauri/src/utils/mobile.rs`        | Mobile helpers (sandbox directories, device id, local file server).                                    |
| `src-tauri/src/utils/init.rs`          | Startup. Desktop creates the window, mobile reuses the window created by the Android runtime.           |
| `src-tauri/tauri.android.conf.json`    | Android specific configuration (the `main` window and the CSP).                                         |
| `src-tauri/gen/android`                | The Gradle project generated by the Tauri CLI. It is committed so that it can be customised.            |
| `src-tauri/capabilities/default.json`  | The permissions of the webview on desktop platforms.                                                    |
| `src-tauri/capabilities/mobile.json`   | The permissions of the webview on Android and iOS.                                                     |
| `scripts/build-android.sh`             | Builds the debug APK with the same steps as the continuous integration.                                |

## Prerequisites

1. **Rust** (stable) with the Android targets:

    ```sh
    rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
    ```

2. **Node.js** and `pnpm` – the same tool chain that is used for the desktop build.

3. **Java 17** – the Android Gradle Plugin requires JDK 17.

4. **Android SDK** with

    - the platform `android-36` (`compileSdk` / `targetSdk` of the generated project),
    - the build tools `36.0.0`,
    - and the NDK `29.0.13846066` (the version the Tauri CLI expects).

    Point `ANDROID_HOME` (or `ANDROID_SDK_ROOT`) at the SDK and `NDK_HOME` at the
    NDK. The Tauri CLI detects both automatically when they are installed in the
    default locations.

## Building

The Android project is generated by the Tauri CLI. It is already committed to
the repository, so a plain build is enough:

```sh
pnpm install

# regenerate the Gradle project (optional, the result is committed)
pnpm tauri android init --ci --skip-targets-install

# build a debug APK
pnpm tauri android build --ci --debug --apk

# build a release APK
pnpm tauri android build --ci --apk

# build an App Bundle for the Play Store
pnpm tauri android build --ci --aab
```

The artifacts are written to:

```
src-tauri/gen/android/app/build/outputs/apk/<buildType>/*.apk
src-tauri/gen/android/app/build/outputs/bundle/<buildType>/*.aab
```

### Running on a device

```sh
pnpm tauri android dev --ci
```

`tauri android dev` builds the application, installs it on the connected
device and starts the logcat output.

### The build script

`scripts/build-android.sh` performs the steps of the continuous integration
workflow (install the dependencies, prepare the Gradle project, build the
debug APK) on the local machine:

```sh
./scripts/build-android.sh
```

### Opening the project in Android Studio

```sh
pnpm tauri android init
pnpm tauri android studio
```

The generated project can also be opened directly with Android Studio, the
`gen/android` folder is a plain Gradle project.

## How the mobile port works

### The main window

Desktop builds create their window at runtime (see `resolve_setup_desktop` in
`src-tauri/src/utils/init.rs`), because the window configuration is part of the
packaged project (`man.json`). Mobile platforms cannot do that: Android creates
the window from the application configuration before the Rust code runs.

`src-tauri/tauri.android.conf.json` therefore declares the `main` window, and
the mobile startup path only makes sure that it is visible.

### Preview

On desktop the preview opens a second webview window (`PreView`). Android only
supports a single webview per activity, therefore the preview is served by the
local HTTP server and opened with the system browser. The custom JavaScript is
injected into `index.html` by the server itself (route
`__pakeplus_preview.html`), because a browser tab cannot be initialised with an
initialisation script.

The command decides what has to be opened:

| Target of the preview | What is opened                                                              |
| --------------------- | --------------------------------------------------------------------------- |
| A page of the local server | The preview route of the server, it serves `index.html` with the custom JavaScript. |
| A page of the application (`./pppwd.html`) | The page is written into the sandbox of the application and served from there. The frontend assets are embedded into the binary on mobile platforms, they are not available as files. |
| A remote website      | The address itself, a browser tab cannot be initialised with a script.        |

The browser does not share its storage with the application, therefore the
project that is previewed is handed over to the backend before the preview is
opened (`preview_context` command) and written into the storage of the served
page. The password page needs it to know the password settings of the project.

The answer of the webview arrives asynchronously, therefore every request gets
its own number. The backend removes the values of the previous preview and
discards an answer that belongs to an older request, a preview never uses the
values of another project.

### Cleartext traffic

The preview and the locally packaged application are served from `127.0.0.1`,
that traffic is plain HTTP. Android forbids cleartext traffic by default, the
generated project therefore ships a network security configuration that permits
it for the loopback interface only:

- `src-tauri/gen/android/app/src/main/res/xml/network_security_config.xml` –
  cleartext is permitted for `127.0.0.1` and `localhost` only,
- `src-tauri/gen/android/app/src/debug/res/xml/network_security_config.xml` –
  debug builds permit cleartext for every destination, a development server is
  often reached through a plain HTTP address.

### Generated Gradle files

Three files of the Gradle project are not part of the repository, they are
written while the application is built:

- `src-tauri/gen/android/tauri.settings.gradle` and
  `src-tauri/gen/android/app/tauri.build.gradle.kts` – written by `tauri-build`
  while the Rust library is compiled for Android. They include the Gradle
  project of the Tauri runtime and of the plugins and add them as a dependency,
- `src-tauri/gen/android/app/tauri.properties` – written by the Tauri CLI, it
  holds the version of the application.

They are listed in the `.gitignore` files of the generated project and must not
be committed.

### Packaging a project locally

`build_local` clones the executable and configures it on desktop. On Android
the project is staged inside the application sandbox
(`<app data>/packages/<name>`), served from `127.0.0.1` and opened with the
system browser. The desktop only installers (`rh.exe`, `sips`, `iconutil`, ...)
are not available, so the corresponding commands return an explanatory error.

### Notifications

`notify-rust` is a desktop only dependency, it needs the freedesktop
notification daemon. Android uses the `tauri-plugin-notification` plugin
instead. The permission state is checked first and the runtime permission is
requested when needed:

```rust
match app.notification().permission_state() {
    Ok(PermissionState::Granted) => {}
    Ok(_) => {
        // the request waits for the answer of the user
        if !matches!(app.notification().request_permission(), Ok(PermissionState::Granted)) {
            return Err("The permission to send notifications was not granted.".into());
        }
    }
    Err(e) => return Err(e.to_string()),
}
app.notification().builder().title(title).body(body).show()?;
```

The request of the permission blocks until the user has answered, therefore the
command runs it on a blocking task of the asynchronous runtime.

`POST_NOTIFICATIONS` is contributed by the plugin itself, so no additional
`<uses-permission>` entry is required in `AndroidManifest.xml`.

### Desktop only dependencies

`open`, `notify-rust` and `machine-uid` are guarded by a target specific
dependency section in `src-tauri/Cargo.toml`:

```toml
[target.'cfg(not(any(target_os = "android", target_os = "ios")))'.dependencies]
open = "5.3.2"
notify-rust = "4.11.7"
machine-uid = "0.5.3"
```

They rely on a shell, on the executable on disk and on the notification
daemon, none of which exist on a phone. The mobile implementations live in
`src-tauri/src/utils/mobile.rs` and use the `opener` plugin, the Android
notification plugin and a random identifier that is persisted in the
application sandbox.

## Continuous integration

`.github/workflows/android.yml` builds a debug APK on every tagged release and
on demand:

1. it installs JDK 17, Node.js, the Android SDK, the NDK and the Rust Android
   targets,
2. it runs `tauri android init` and `tauri android build --apk`,
3. it uploads the resulting APK as a workflow artifact.

## Troubleshooting

| Symptom                                            | Solution                                                                                                              |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `Java not found in PATH`                            | Install a JDK 17 and make sure `JAVA_HOME` points to it.                                                               |
| `Android NDK not found`                             | Install `ndk;29.0.13846066` with the SDK manager and export `NDK_HOME`.                                               |
| `failed to run 'cargo metadata'`                    | Install Rust – the Tauri CLI needs the crate metadata to detect the project layout.                                   |
| The preview does not open                           | The preview is opened with the system browser; make sure a browser is installed on the device.                          |
| The preview shows an empty page                     | The local server serves `127.0.0.1`, check that the network security configuration of the project is in place.            |
| No notifications                                    | Android 13+ requires the `POST_NOTIFICATIONS` runtime permission, it is requested when the first notification is sent.   |
